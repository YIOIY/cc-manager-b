# 仪表盘加料 + 帮助文档改版（2026-11-13）

## 为什么做

用户反馈：帮助文档「展示效果不太好」，仪表盘「太单调，要更多的数据跟内容」。两处都只改展示和读取，不改业务流程。

## 目标 / 非目标 / 反目标

- 目标（仪表盘）：一屏看到机队的配额占用、消费节奏、账号构成和最近的上号结果，数字都来自已有的同步数据。
- 目标（帮助文档）：进来先看到路线和分类而不是一篇文章；文章里的按钮名、步骤、状态一眼能扫到；能搜到并看到命中的上下文。
- 非目标：不新增同步任务、不改账号/账单页、不做图表库引入、不做文档在线编辑。
- 反目标：为了「看起来丰富」放没有依据的数字；仪表盘某个接口失败导致整页空白；没有网页通道的部署看到一堆报错。

## 方案比较

仪表盘数据来源：

| 方案 | 做法 | 取舍 |
| --- | --- | --- |
| A 新增一个只读聚合接口（采用） | `GET /dashboard/insights` 一次返回新面板需要的全部聚合 | 现有 `/dashboard`、`/dashboard/attention` 不动；新面板失败不影响旧面板；一次请求 |
| B 往 `/dashboard` 里继续加字段 | 所有内容一个接口 | 接口越来越重，任何一段出错整页没有数据 |
| C 前端拉账号列表自己算 | 不改后端 | 账号多了要分页拉全量；小时消耗需要快照表，前端拿不到 |

帮助文档呈现：

| 方案 | 做法 | 取舍 |
| --- | --- | --- |
| A 首页 + 文章两种视图，内容仍是结构化数据（采用） | 无 `topic` 时显示首页（搜索、上号路线、分类卡片、常见问题）；有 `topic` 时显示文章 | 沿用现有内容和测试；新增少量块类型即可 |
| B 改成 Markdown + 渲染库 | 内容写 Markdown | 要引依赖和处理 HTML；按钮名高亮、路线图仍要自定义 |
| C 只调样式 | 布局不变 | 解决不了「进来就是一篇长文」的问题 |

## 设计：仪表盘

新接口 `GET /api/v1/dashboard/insights`（`dashboard.view`）：

- `usd_cny_rate`：所有启用连接的平台汇率一致时返回该值，否则 `null`（只显示人民币）。
- `fleet`：已关联且平台仍在列的账号的 `accounts`、`cost_fen_total`、`input_tokens`、`output_tokens`、`avg_five_hour_percent`、`avg_week_percent`。
- `quota[]`：每个账号 `account_id, account, alias, status, five_hour_percent, five_hour_reset_at, week_percent, week_reset_at, cost_fen`，按 5 小时占用从高到低，最多 50 条；没有用量的账号排在最后。
- `hourly[]`：最近 24 个整点小时的 `{hour, cost_fen}`，由用量快照里累计花费的增量得出（负增量忽略）。
- `composition`：`by_delivery`（待上号/上号中/已上号/失败/待确认，口径同账号列表）、`expiry`（`expired`、`within_7`、`within_30`、`later`、`unknown`，按连接时区的今天，平台到期日优先）。
- `recent_jobs[]`：最近 6 条上号任务 `{id, account_id, account, connection, state, code, updated_at}`；仅当用户有 `jobs.view`，否则为 `null`。

页面：

```
[平台账号][接近限额][今日消费 ¥/$][7 天消费 ¥/$ · 日均 · 较前一日]
累计花费 ¥/$ | 累计 Token 输入/输出 | 平均占用 5 小时/7 天 | 30 天内到期      ← 一行账本式数字
[需要处理]                         [消费：7 天柱 + 近 24 小时逐小时柱 + 按模型/按账号]
[配额看板：每个账号一行，5 小时与 7 天两条刻度条，80% 处有刻线]   [账号构成：平台状态、上号状态、套餐、到期]
[最近上号]                         [系统状态：两个同步、代理、任务、版本、汇率]
```

- 「配额看板」是这页的主角：行密、可点（跳到该账号），其余面板保持安静。
- 三个接口各自加载、各自失败：某个失败只在对应面板里提示。
- 去掉面板标题上方的英文小标签。

## 设计：帮助文档

- 内容模型：主题加 `summary`（一句话）、`icon`、`area`（常见问题的分组：上号 / 平台连接 / 金额与仪表盘 / 登录）；新增块 `flow`（路线节点）和 `table`（表头 + 行）。文字里的「按钮名」自动渲染成按钮样的小标签。
- 首页（无 `topic`）：大搜索框；「上号路线」五个节点（准备 → 连接账号 → 补充资料 → 确认上号 → 查看结果），每个节点可点到对应主题；操作手册卡片（图标、标题、一句话）；常见问题按分组列出。
- 文章页：左侧目录保留；正文步骤改成带序号的时间线，状态说明用表格；文末「相关主题」卡片和上一篇/下一篇；顶部可回到首页。
- 搜索：输入后（首页和文章页都一样）显示结果列表，每条带命中处的上下文并高亮关键字；无结果时给出提示。
- 上号弹窗里的两个链接（`?topic=onboard`、`?topic=device-id`）保持有效。
