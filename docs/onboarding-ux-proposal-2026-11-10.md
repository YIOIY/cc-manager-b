# 新建上号交互方案

日期：2026-11-10。状态：设计提案，未修改应用功能。

## 设计结论

采用「连接账号 → 补充资料 → 确认上号」三步向导，替换当前同时展开的长表单。沿用现有浅色、青绿色主色与圆角风格，减少嵌套卡片、重复说明和技术字段。

核心目标是让用户看到授权的成果，并理解剩余资料的用途。OAuth 完成代表账号已连接；资料齐全代表可以提交；平台处理成功才代表上号成功。三种状态分开表达。

## 当前界面为什么显得生硬

- 授权前就展示账号、密码、日期和完整凭证等多个区域，用户无法判断哪些会自动填写。
- 授权完成后仍留在长表单中，用户看不到明确的阶段完成与下一步。
- 缺项清单、字段本身和帮助文案重复呈现同一信息，增加视觉负担。
- 「凭证」「设备 ID」「交付密码」混在一起，容易让用户误以为授权失败，或者需要再次输入登录信息。
- 代理已经有下拉选择，但缺少新建入口，空值又代表另一种网络行为，用户难以预判最终上号会使用什么。

## 方案比较

| 形式 | 优点 | 局限 |
| --- | --- | --- |
| 三步向导，推荐 | 阶段清楚，每屏有单一任务；适合授权后补资料 | 多两次继续操作，需要保持表单状态 |
| 单页折叠分组 | 改动较少，熟练用户能快速操作 | 长表单和混杂的任务预期依然存在 |
| 独立全屏创建页 | 适合大量批量配置、复杂规则 | 当前单账号流程偏重，也打断列表操作 |

首版保留弹窗载体，建议桌面宽度约 720–780px，自适应视口；正常状态减少滚动，错误、帮助和小屏允许内容纵向滚动。标题与操作区在实际应用中保持可达，不强行把所有内容压入固定高度。

## 第一步：连接账号

顺序：上号平台 → 代理来源 → Claude 登录。

标题「添加 Claude 账号」，副标题「连接账号，补充上号资料，确认后提交」。平台提前选择，使后续必填项、代理规则与交付目标一致。

登录前说明一次：

> 授权后填入账号与凭证；交付密码、订阅日期和设备资料将在下一步补充。

主按钮「登录 Claude」。在现有授权实现上，点击后展示打开授权页的动作及授权结果输入框；保留链接复制作为打开失败的后备入口。链接与粘贴区域只在等待授权状态出现。不能在尚未支持回调自动接收时声称自动完成。

授权成功后，在原位置替换成紧凑的成功摘要：

> ✓ 账号已连接
> learner@example.com · Pro
> 已填入账号与授权凭证，继续补充上号资料。

不直接跳屏；底部主按钮变为「继续，补充资料」，让用户先确认授权账号是否正确。「更换账号」为次级操作；新账号重新识别后，旧账号的密码、设备资料和订阅日期不可自动沿用，避免混用。

「已有完整凭证？从 JSON 导入」放在低强调折叠入口，复用已有解析能力。导入与 OAuth 共用后续缺项检查；完整导入可直接进入确认页，不强迫重复填写。

## 代理交互

代理来源使用与用户参考图一致的三个单选入口：自动分配 / 选择已有代理 / 填写新代理。不要叠加另一个代理弹窗。

| 来源 | 展开内容 | 规则 |
| --- | --- | --- |
| 选择已有代理 | 可搜索下拉：名称、协议、主机、端口 | 首版默认入口；禁用项不可选；认证信息由服务端读取，浏览器无需查看或重填 |
| 填写新代理 | 一个完整地址输入框，解析后可展开协议、主机、端口和认证字段 | 继续前校验并创建代理，成功后取回 ID，随后 OAuth 与上号使用同一 ID；创建失败保留本页输入 |
| 自动分配 | 分配结果摘要，以及明确的失败恢复入口 | 后端能力未完成前不可点击；有完整规则后再开放，不能以取列表首项代替分配 |

新代理首版明确提示「继续时保存到代理池」，不提供尚未实现的临时代理复选框。若 OAuth 后取消，已创建代理保留在池中，提示可继续复用，不自动删除共享资源。界面仅显示脱敏地址。

自动分配后续需要：

1. 定义候选资格：至少启用状态、目标平台匹配要求，以及是否允许共享。地区、占用和健康筛选均须有实际数据支持。
2. 服务端原子选取并预留代理，授权会话与提交使用同一预留结果，避免并发拿到不允许共享的同一代理。
3. 定义预留有效期、取消或超时释放、提交成功转为正式绑定，以及失败后的重新分配。
4. 无候选时提示「暂无符合条件的代理」，提供已有代理和新建入口，不静默转为直连。

已有代理下拉当前只有基本字段。若展示延迟、出口 IP 或检测时间，需要接入代理检测数据，标记为「最近一次检测」，不得把本地探测通过说成目标平台可用。

网络说明放在帮助文案中：此选择控制服务端授权请求与上号代理；浏览器登录仍使用浏览器自身网络。

更换代理的规则：等待授权时让旧链接失效并明确提示重新生成；授权已完成后，返回第一步更换代理时明确提示需要重新授权，保留其他已填写资料。不要默默丢失内容，也不要静默替换最终交付代理。

## 第二步：补充资料

顶部固定为一行账号摘要：头像占位、邮箱、套餐和「授权完成」。不再重复出现可编辑邮箱和登录卡片。

主体分为三类：

| 信息 | 展示方式 |
| --- | --- |
| 已从授权得到且可用的邮箱、套餐、注册日期 | 摘要与「查看已获取信息」中展示，注明来源；必要的修正操作就近提供 |
| 当前目标平台要求、但仍缺失的信息 | 正常展开输入区，仅列待填字段；已补充的字段继续留在本步，避免输入时跳动 |
| Token、UUID、组织标识等完整凭证 | 高级详情默认折叠，敏感值隐藏；异常缺项时定向展开相关位置 |

按照当前接口，常见待补充项为交付密码、订阅开始、订阅结束及设备资料。若套餐或注册日期未识别，也加入当前待填区，不能假定固定只有四项。

具体规则：

- 「交付密码」说明用途：平台要求的账号密码，授权不会提供。不伪装成授权重试，也不随意创建密码。
- 日期按订阅账单填写；不根据 Token 到期时间计算，也不默认写成今天加一个月。
- 套餐、注册日期注明「授权识别」「导入」或「手动填写」；识别不到则待补充，不展示虚构默认值。
- 交付地区按当前接口展示 US，同时注明平台范围；不能说是 OAuth 已识别。
- 设备资料使用「从已有有效凭证导入」辅助入口。现有文档尚未明确设备 ID 的完整获取规则；必须能明确指出缺项，不能随机生成或暗示 OAuth 可以补齐。
- 如果用户没有平台要求的设备资料，交互优化本身无法消除阻断。需另行确认设备资料来源，或调整自己控制的平台协议。
- 备注、注册设备等可选信息统一放入「更多资料（选填）」中。

将现有缺项清单改为紧凑的「待补充 N 项」，保留跳转与校验能力，不再重复铺开一张与表单同内容的大清单。用户点击继续时定位第一个未填或非法字段，错误显示在字段附近。

## 第三步：确认上号

只读核对账号、套餐、订阅周期、平台、地区、注册日期及所选代理。敏感数据仅显示「已填写」，不重新展示 Token、密码或代理认证信息。

资料完整时主按钮「确认并上号」；保留「上一步」。提交期间防重复点击。提交成功只显示「已提交，等待平台处理」并进入进度或结果页；真正收到平台成功结果才展示「上号成功」。

字段校验失败返回对应步骤并保留输入。平台拒绝时显示实际可操作的原因与重试入口；重试应复用已有记录/任务机制，不能重复创建账号。

## 状态、返回与异常

- 步骤切换共享一份表单状态，返回不清空已填写内容。
- 授权取消、失败或链接过期：在第一步局部提示，可重新生成链接；保留代理与平台选择。
- 平台变更：重新计算交付规则与缺项；保留兼容值，对不兼容值明确提示，不假装已经满足新平台要求。
- 关闭前仅在已有授权或存在输入时提示资料尚未提交；没有修改时直接关闭。
- 新获取的敏感凭证沿用当前表单内存保存方式；不因预览或步骤切换写入 localStorage。
- 「保存草稿、稍后补充」不作为首版承诺。若后续加入，必须单独确认草稿接口、敏感信息存储和过期行为。

## 落地范围

### 首版

1. AccountFormDialog 改为三步容器，复用现有 account-form 状态、校验及提交能力。
2. ClaudeOAuthPanel 根据未开始、等待授权、已授权、失败四种状态替换显示内容。
3. AccountCompletionChecklist 改为步骤内紧凑缺项反馈，避免与实际输入重复。
4. 抽出可复用代理选择区域；复用 ProxyFormDialog 中的地址解析思路和已有代理创建能力。
5. 增加确认页，以及真实提交状态的文案区分。

### 后续能力

自动分配涉及后端规则、预留与释放；完整草稿涉及存储与过期。这些能力不应夹带在纯 UI 改版里假装已经具备。

## 验收重点

- 授权前不展示全部业务表单；授权后明确显示所连接账号与自动获取成果。
- 缺项区依据真实数据变化；已获取字段不用重复输入，未获取字段不会被默认值掩盖。
- 已有、新建、禁用和无可用代理状态都有明确路径；选中代理始终与实际请求一致。
- 返回步骤保留数据；更换账号或代理不会混用凭证或静默造成数据丢失。
- 日期顺序、缺设备资料、授权失败和重复提交有可理解的处理方式。
- 小屏可操作，键盘能完成流程，错误可定位；展示凭证时默认脱敏。

## 本次交付与证据边界

已提供三步交互原型：支持已有/新代理切换、模拟授权、缺项提示、填入示例资料、核对与模拟提交。示例账号与设备资料不用于真实请求；自动分配明确标记为待接入。

依据当前仓库的 AccountFormDialog.vue、AccountCompletionChecklist.vue、account-form.ts、ProxyFormDialog.vue、lookups.go、onboard.go 及 platform-contract.md、claude-oauth-onboarding.md 制定。本文描述的是项目当前实现与拟议改动，不构成对 Claude 官方接口行为的重新确认；真实授权和供应商链路仍需独立联调。
