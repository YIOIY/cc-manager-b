# 账号卡片：人民币 + 美元金额与汇率（2026-11-13，当日修订）

## 为什么做

账号卡片的「累计花费」只有人民币。用户要同时看到美元金额和所用汇率，并去掉卡片底部一直为空的「请求 / 输入 / 输出」三行。

## 修订说明

首版（提交 dcaf749）用了公开的市场参考汇率（当日 6.6683），口径是错的，用户指出「汇率应该根据平台数据计算」。核实平台后台的前端代码后确认：

- 接口只返回人民币 `cost`（`cpa_usage.cost` 单位百万分之一元），**不返回汇率**。
- 平台卡片的显示函数是 `¥(cost/1e6) / $(cost/1e6/7.2)`，标注「汇率 7.2」「美元金额按固定汇率 1 美元 = 7.2 人民币换算」。
- 账单页注明「若是海外厂商，汇率已乘 7.2，此页面均按官方原价计算」「2026年9月汇率由7.3调整为7.2」。

即人民币 = 美元原价 × 平台固定汇率，美元应按同一固定汇率反算。本文档为修订后的设计。

## 目标 / 非目标 / 反目标

- 目标：卡片「累计花费」显示 `¥人民币 / $美元` 和汇率，数值与平台后台一致；汇率可在平台调整时修改；删除三行进度条。
- 非目标：不改仪表盘、账单页的金额展示；不自动探测平台汇率变化。
- 反目标：用市场汇率换算；访问外部汇率服务；没有汇率时显示一个错误的美元数字。

## 方案比较

| 方案 | 做法 | 取舍 |
| --- | --- | --- |
| A 每条平台连接保存固定汇率（采用） | `platform_connections.usd_cny_rate`，默认 7.2，在平台设置里可改 | 与平台口径一致；平台调整时改一个值；不同供应商可以不同 |
| B 代码里写死 7.2 | 常量 | 最简单，但平台已经调整过一次（7.3→7.2），再调整要发版 |
| C 从平台前端脚本里抓取汇率 | 定时下载平台页面脚本，匹配其中的汇率 | 能自动跟随，但依赖压缩后的脚本内容，平台一改版就失效，且失败时无从判断 |
| （已废弃）自动取市场参考汇率 | 首版做法 | 口径错误，美元金额偏差约 8% |

## 设计

- **存储**：迁移 v12 给 `platform_connections` 加 `usd_cny_rate REAL NOT NULL DEFAULT 7.2`，并删除 v11 建的 `exchange_rates` 表。
- **接口**：连接的列表返回 `usd_cny_rate`；新建和修改可带 `usd_cny_rate`（1–20 的数字，否则 422 字段错误），不带则保持原值/默认值；修改写审计 `connection.usd_rate_set`。账号的 `platform` 块带出所属连接的 `usd_cny_rate`。移除 `GET /exchange-rate` 和后台取汇率任务。
- **前端**：`PlatformUsageBlock` 接收 `usdRate`，显示
  ```
  累计花费
  ¥751.04 / $104.31
  汇率 7.2 · 平台固定汇率
  ```
  悬停提示「美元金额按平台固定汇率 1 美元 = 7.2 人民币换算」；没有汇率时只显示人民币。连接表单增加「美元汇率」输入。
- **卡片**：删除「请求 / 输入 / 输出」三行及其只为它们服务的计算。
- **帮助文档**：常见问题「卡片上的美元金额和汇率是怎么来的」按平台口径重写。
