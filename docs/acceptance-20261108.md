## 2. 端到端（干净数据库）

### 2.1 登录与基础
- 错密码提示「用户名或密码错误」；正确密码进入工作台，会话返回管理员角色与 30 项权限。
- 请求体超限返回 413；重复账号返回 409；这些错误在控制台只表现为预期的资源状态码，无脚本异常。

### 2.2 业务流
- 新建平台连接 / 代理（带认证）/ 账号草稿均 201。
- 账号上号 202 `queued`，相同幂等键重放 202 不重复建任务；worker 对不可达供应商记录 `unknown: SUBMIT_OUTCOME_UNKNOWN`，不盲目重试。
- JSON 导入预览正确区分 1 条有效 / 1 条无效，提交创建 1 条。
- 任务中心服务端分页返回正确。

### 2.3 RBAC
- 通过角色编辑器只开启「代理池」「任务中心」两个页面并勾选「发起本机检测」，已选 3/30；角色卡片显示可见页面。
- 通过用户表单创建 `inspector` 绑定该角色，表单实时显示「合并后共 3 项权限」。
- 以 `inspector` 登录：落地页为代理池，导航只有两项，直接访问 `/accounts` 被跳回；接口 `GET /proxies`、`GET /jobs` 200，`POST /proxies`、`GET /accounts`、`GET /users`、`GET /dashboard` 403，`POST /proxies/{id}/test` 放行（404 为代理不存在）；页面上无新增 / 修改路径按钮。
- 管理员从另一会话停用 `inspector`：其进行中的会话下一次请求即 401 并跳回登录页；再次登录返回「用户名或密码错误」。
- 自助改密输入错误当前密码返回「当前密码不正确」。
- 不能停用自己（`SELF_DISABLE`）。
- 审计事件 `actor` 为真实用户名（`admin:user.create`、`inspector:auth.login`、`system:account.submit.failed`）。

### 2.4 发现并修复的缺陷
- **被吊销会话后无法直接重新登录**：跳回登录页后表单仍带旧 CSRF 令牌，提交返回「会话验证失败」，需刷新页面。修复：收到 401 时自动获取新的匿名会话；登录遇到 `CSRF_FAILED` 自动刷新会话并重试一次。补充单元测试；复验：被停用用户跳回登录页后，不刷新即可用管理员账号登录成功。
