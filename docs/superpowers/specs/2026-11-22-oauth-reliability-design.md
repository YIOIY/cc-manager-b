# OAuth 剩余项改造设计草案

日期：2026-11-22

状态：已完成可行性判断与实现设计；待确认设计后实施。本文不是完成报告。

## 目标与基线

以用户的 13 项要求和本次调用链核查为验收输入，减少重复授权、重复兑换、并发凭证覆盖和无效重试。保留当前 Go / SQLite / Vue 架构，不引入新的运行时服务。

代码基线：`dd1673c`。当前已有单进程 3 并发兑换闸门、提交阶段账号锁、部分冷却、部分错误分类与前端倒计时。缺口集中在授权会话生命周期与各写入入口之间。

## 实现选择

推荐：有期限的授权会话 + 账号串行锁 + 分阶段兑换结果保存。

只增加几个 mutex 无法表达“用户已经获得 token、尚未提交”的阶段，也无法处理取消、过期和响应丢失。引入独立分布式工作流服务则超过当前单进程架构需要。本次在既有服务内补全状态机，并明确单进程边界；若生产存在多个服务进程，必须增加数据库租约或共享协调后才能宣称跨进程串行。

## 1. 授权会话与账号写入

- 会话状态：等待授权、兑换中、已取得令牌待资料、可提交、已提交、已取消、已过期。
- 同一 owner 的普通 start 原子查找或创建一条活动会话。重复请求返回同一链接；不同代理参数返回明确冲突，要求显式作废重取。
- 会话绑定 owner、accountID 或临时身份、所选代理快照、网络配置版本、同一服务器端 HTTP client。
- 已有账号从 start 起占用账号写权限，持续到提交完成、显式取消或过期。所有账号凭证、代理绑定和相关资料写入都接入同一协调机制；worker 遇占用保持排队。
- start 发现该账号存在 queued/running 提交任务时返回 409，不再发起探测或授权。
- 成功兑换后保留服务器端已取得的结果，返回供最终提交携带的会话标识；UI 隐藏授权码不等于释放服务器端账号占用。
- 提交校验 owner、账号身份、会话状态和出口快照；并发提交只有一个能获得执行权。成功响应丢失时可重放成功结果，避免再推一次。
- 到期清理、取消、错误退出和服务关闭必须释放占用与闲置连接。清理不得中断已经获得执行权的供应商写入。
- 共享代理变更或账号分配影响多个账号时，按稳定顺序取得相关账号锁，或明确拒绝与授权占用冲突的修改。

## 2. 并发闸门与冷却

- 保留并发上限 3、用户写令牌桶与有限排队；start 探测也纳入同一外部 OAuth 请求闸门。
- 获得闸门额度后重新检查会话状态与冷却，避免排队期间新产生的 429 被绕过。
- 新号使用 owner/session 临时键；获得邮箱后建立邮箱冷却键，保留已建立的临时键关联。已有账号始终传 accountID，与是否选择代理池无关。
- Retry-After 同时支持秒数与 HTTP 日期，保留合理下限，移除业务时长上限；解析时处理数值溢出。
- 同一账号的后续响应只能延长，不能缩短已有冷却；所有 retry 路径均遵守冷却。
- 前端按绝对截止时间计算剩余秒数；按钮、回车、粘贴自动兑换、start、显式重取统一检查。后端仍为权威判断。
- 前端请求时限覆盖后端排队与执行预算；取消请求不会触发新的授权。

## 3. 分阶段恢复与错误语义

- token 兑换与 profile/roles 查询分开。成功取得 token 后立即保存到会话；后续资料请求失败，只重试对应资料阶段。
- 同一会话只能有一次在途兑换；重复请求获得已有阶段/结果，不并发发送同一 code。
- 五档动作：瞬时网络/格式错误可重试；429 等待；可明确归因到代理连接的错误提示检查代理；401/403 提示身份或出口被拒绝；供应商拒绝按状态和阶段处理。
- 保留错误 stage、上游状态、耗时及可重试动作，不返回或记录授权码、token、代理密码及原始响应体。
- 代理重试最多一次：仅重建相同出口的客户端，不更换代理配置。只对可确认请求尚未发出的失败自动重试；发送后响应丢失不能声称“code 未使用”，也不盲目重放。
- 本地粘贴串格式不正确仅清错误输入，保留仍有效的会话。确认 code/state 无效或明确已消费时要求显式重签；401/403 本身不等同于 code 已消费。
- 供应商提交采用动作枚举分流，移除仅凭 HTTP >= 500 一律可再次推送的判断。结果不确定或“平台已成功、本地保存失败”进入核实/本地修复路径。

## 4. 探测与出口一致性

- 探测既有真实 token 端点，读取状态；连接失败、拒绝访问、429、5xx、非 JSON 分开表达。GET 的 405 可代表端点可达，不能等同于 POST 授权成功。
- 包括保存的代理回退路径，所有 start 都使用绑定后的服务器端 client 探测。
- pending 固定解析后的代理地址及前置代理配置。exchange 不重新读取可变代理配置；worker 不再用新解析的地址静默覆盖已绑定凭证。
- 出口配置发生变化时返回明确冲突，要求重新授权；手动导入的凭证和历史未带绑定信息的凭证采用显式迁移/确认规则，不伪造绑定证明。
- 限制：浏览器打开的第三方授权页不使用后端 HTTP client；固定代理 URL 也不保证供应商轮换代理的实际出口 IP 不变。本次可以保证服务器端配置与 client 连贯，浏览器出口及代理是否黏性需要部署侧验证。

## 5. 设备、新鲜度与请求头

- 在所有凭证写入口统一“显式有效设备 ID → 已保存设备 ID → 一次性生成并持久化”。校验函数不再产生随机副作用。
- worker 重试、重新提交、重授权继承同一已持久化设备 ID。旧数据缺值时在账号锁内完成一次迁移。
- 持锁比较新旧 last_refresh/expired，阻止较旧凭证覆盖较新凭证；相同时间但 token 不同且无法判断先后的情况返回冲突，避免猜测。
- 过期检查和数据库版本检查继续保留，不能相互替代。worker 在提交前读取锁保护下的最新已持久化快照。
- 固定应用自身的 UA 与 Accept-Language，不随机化、不伪装成不存在的客户端版本；版本头只用于已确认支持的端点。
- 既有 refresh_token 继续保存在凭证与供应商 payload 中。暂不向 authorization_code 请求额外追加旧 refresh_token；公开平台 OAuth 文档区分 authorization_code 与 refresh_token grant，且公开文档端点不同于本仓库的现有流程，不能据此证明额外字段可用于身份关联。

## 6. 最小观测

- 记录每账号 429、重授权尝试与结果；邮箱和 token 不作为公开指标标签。
- 输出低基数 OAuth stage/result/status-class 指标，探测成功率、探测和兑换时长直方图、闸门排队时长/在途数。
- 直方图可计算 P95；每账号细节放在受权限保护的事件记录或审计中，避免公开 metrics 暴露账号标识和高基数标签。
- 用匿名会话关联 ID 串起探测、兑换、资料查询与提交，错误详情携带相同关联信息。

## 验收条件

- 并发 start 返回同一会话，只发生一次探测；并发 exchange 对同一 code 只发送一次 token 请求。
- 重授权期间 worker 和其他账号写入不能穿透；成功、取消、过期后可恢复提交。
- queued/running job 阻止重授权 start，且不消耗新的上游请求。
- 新号及选择代理池的旧号都进入冷却；超过一小时的 Retry-After 原样遵守；获得闸门后再次检查。
- 倒计时期间按钮、回车、粘贴、重取均不能产生兑换/重签请求。
- token 成功后 profile 返回 429，再次操作不重新兑换 code；响应丢失后的重复请求恢复已保存结果。
- 只有连接失败归类为代理不可达；403、429、5xx、非 JSON 的动作和 stage 可区分。
- 授权后修改代理配置被检测，worker 不覆盖凭证绑定的出口。
- 重试及重新提交沿用设备 ID；旧快照被拒绝；本地提交成功但响应丢失不重复推送。
- 指标覆盖成功/失败/等待，日志与指标不含秘密。
- Go 测试、账号/OAuth 并发 race 测试、前端单元测试、类型检查、构建和相关 E2E 通过。
- 使用模拟 token/profile/供应商端点完成故障矩阵；真实账号验收与上游协议兼容性另列结果，未经实际调用不声称已验证。

## 交付与恢复

实施前保存原始文件 SHA256 与基线，在副本/隔离分支修改，保留现有用户修改。交付变更、测试命令及原始结果、13 项完成矩阵和恢复说明。数据库若新增结构，只做兼容性新增；回滚需要同时说明旧版本对新增数据的处理。

本草案仅新增设计文件，没有修改业务代码，没有操作真实账号，没有发起授权、提交或部署。
