# 实施路线、任务拆分与验收计划

> v1.0 设计稿，2026-11-04；2026-11-08 按实际代码更新勾选状态。已勾选项以仓库内实现与测试为准，未勾选项仍为待办；平台未确认能力不以Mock结果代替真实验收。

## 1. 实施原则

- 优先完成“页面录入已有账号 → 代理 → 完整凭证 → 预检 → 上传 → 状态与消耗”纵向链路。
- 自动注册、购买订阅、模型转发不进入项目任务列表。
- 完整凭证手动填写与JSON导入是首版能力；自动授权/刷新在规则确认后独立实施。
- 前端不直连供应商；后端不依赖用户Chrome登录会话。
- 各阶段用Mock SupplierAdapter和受控测试代理验证，真实凭证仅在最终获准的联调环境使用。
- 功能完成必须包含对应失败路径，不能仅以页面可打开或上传HTTP返回成功验收。

## 2. 阶段与交付物

| 阶段 | 目标 | 核心交付 | 前置条件 |
| --- | --- | --- | --- |
| P0-A | 工程骨架与契约 | Go服务、Vue工程、OpenAPI schema、迁移框架、配置、基础CI | 本文档评审完成 |
| P0-B | 本地账号与秘密 | 登录、草稿CRUD、四段表单、凭证PUT/PATCH、加密与审计 | P0-A |
| P0-C | 代理池与导入 | 代理管理、检测、固定绑定、JSON预览与入库 | P0-B基础数据模型 |
| P0-D | 预检与任务 | 统一校验、版本、幂等、持久队列、模拟上传和重启恢复 | P0-B/C |
| P0-E | 平台交付 | 真实SupplierAdapter、接收ID、验证跟踪、结果未知处理 | P0-D；OpenAPI Token和真实凭证样本获准可用 |
| P0-F | 消耗闭环 | 指标与日账单采集、详情和总览、修订与新鲜度 | P0-D；Mock可先开发，真实数据验收依赖P0-E |
| P0-G | 部署与验收 | 备份恢复、失败恢复、负载基线、可运行发布包与说明 | 所有首版功能 |
| P1 | 后续能力 | 经确认的授权/刷新、多角色、PostgreSQL、通知等 | 存在明确需求及平台规则依据 |

阶段之间可在契约固定后并行开发前端和后端；数据库约束、状态定义与ProviderAdapter由同一负责人集成，避免各自猜测字段。

## 3. 具体任务清单

### 3.1 P0-A：工程与契约

- [x] 创建Go模块、标准HTTP路由、配置读取、健康/就绪检查。
- [x] 创建Vue3+TS+Vite工程，接入路由、组件库和Fetch封装。
- [ ] 将[API契约](api-contract.md)转为OpenAPI3.1，生成前端DTO。
- [x] 建立SQL migrations及本地临时数据库测试工具。
- [ ] 定义SecretBox、SupplierAdapter、ProxyProbe、Clock等可替换边界。
- [x] 建立CI：Go测试/静态检查、TS类型检查、lint、前端构建。
- [x] 锁定维护中的依赖版本，记录许可证与版本选择，不自动引入无关包。

完成证据：最小服务可启动、前端可加载、Mock API一致、迁移可重建、CI通过。

### 3.2 P0-B：登录、账号与凭证

- [ ] 一次性管理员初始化，无公开默认密码；服务端Session和CSRF。
- [x] 账号新增/编辑/详情/列表/本地归档，乐观锁与重复身份规则。
- [x] 四段表单：基础信息、代理、凭证、补充信息。
- [x] 后端保存草稿，最小必填账号标识；缺项和就绪度独立返回。
- [ ] 凭证逐字段编辑、完整替换、局部合并；保留未知字段。
- [x] 密码和Token加密存储，元信息只返回字段存在性与安全摘要。
- [x] 编辑已有秘密时省略未修改字段，不把空字符串/掩码发送为新秘密。
- [ ] 每次变更记录安全审计；已交付配置变化标记out_of_sync。

完成证据：只用表单可保存和补全账号；刷新页面不泄露秘密；并发编辑返回409；后端拒绝绕过前端校验的非法输入。

### 3.3 P0-C：代理池与导入

- [x] 代理CRUD、启停、归档、出口IP/延迟检测和历史。
- [x] HTTP/HTTPS/SOCKS5/SOCKS5H协议与认证、IPv6、域名、URL编码测试。
- [ ] 代理允许网络范围、DNS解析检查、重定向规则和固定连接地址。
- [ ] 固定绑定、容量摘要、关联账号页面；故障只预警，不静默换已交付账号出口。
- [ ] 修改代理端点/认证后，关联交付统一标记out_of_sync。
- [ ] JSON回填：可比较、可确认、可取消；导入代理来源冲突要明确处理。
- [x] 后端导入preview、加密短期会话、逐条commit结果与重复策略。
- [ ] 批量代理文本导入使用相同preview机制，不让浏览器任意指定探测URL。

完成证据：从代理新增到账号绑定闭环；代理密码特殊字符不破坏连接；导入不自动上传平台；无效行不污染已存在账号。

### 3.4 P0-D：任务与预检

- [x] 一套Validator供表单、导入、预检和Worker执行前复用。
- [ ] 预检检查完整性、时区格式、套餐/凭证有效期、代理新鲜度、配置版本与本地重复交付。
- [x] 任务表、租约、心跳、退避、停止与进程恢复。
- [x] 上传意图、幂等记录、交付尝试在本地事务中创建。
- [ ] 生成加密上传快照，固定账号/凭证/代理/平台连接版本。
- [x] 明确区分发送前失败、平台拒绝、平台接收、发送结果未知。
- [ ] 任务列表/详情、轮询、批量父子任务和逐项失败。
- [x] 恢复发送中的任务时不自动重新上传；先标不确定并请求人工核对。

完成证据：重复点击/网络重试只产生一个上传意图；模拟响应丢失或Worker崩溃时不会重复创建远端账号。

### 3.5 P0-E：真实平台交付

- [x] 管理员配置平台origin、OpenAPI Token、时区、允许套餐。
- [x] 实现三个已文档化接口；校验TLS与响应体，HTTP秘密不写日志。
- [ ] 请求只用完整、已明确代理来源的真实凭证，不补虚构字段。
- [ ] 上传响应id/alias持久化，排队验证并读取远端状态。
- [ ] 5分钟未完成只提示；check_fail/online/未知状态正确呈现。
- [ ] 结果未知时人工关联平台ID，保存操作者确认和审计。
- [x] 平台401/403不转换成Claude账号封禁；未配置OpenAPI Token时清晰阻断。
- [ ] 已交付账号本地编辑不发送重复创建，也不显示远端更新成功。

真实联调门槛：由用户准备并在受控后台输入一个允许交付的账号、完整凭证、代理与平台OpenAPI Token。开发者不能从浏览器会话自行提取密钥，也不能在未经授权的生产平台批量创建测试数据。

完成证据：单个已获准账号被平台接收并关联到正确本地记录；验证/异常结果可追踪。若平台不接收当前套餐，记录具体业务拒绝，不能用Mock成功替代。

### 3.6 P0-F：同步与看板

- [x] 指标读取显式aggregate=false；分批不超过100账号；上游窗口不超过7天。
- [ ] 每次覆盖窗口累计快照，避免重复累加。
- [x] 离线账单逐日采集、整数分保存、唯一约束与revision。
- [x] 处理近3/7天延迟修订；补采受90天边界和平台限流约束。
- [ ] 账号详情、跨账号查询、日趋势、金额与Token来源标识。
- [x] null与0分开；缺日期、部分失败、旧数据和最后同步时间可见。
- [ ] 不展示实时cost金额，不从Token推算官方订阅百分比，不把金额叫收益。
- [x] 页面轮询只查本地；后台采集独立运行，页面关闭不影响任务。

完成证据：同一组上游累计数据采集多次不改变总额；账单修订替换而非叠加；101账号自动分两批且可准确显示部分失败。

### 3.7 P0-G：运维与发布

- [x] 本地与容器部署模板，数据/密钥目录独立，首次初始化说明。
- [x] SQLite一致性备份与恢复，数据库和密钥的权限要求。
- [ ] 恢复测试覆盖待执行、发送中、结果未知任务和已修订账单。

- [ ] 单机目标规模基线：1000账号/500代理列表分页与正常同步队列。
- [x] 编写运行手册：配置、升级、备份、恢复、任务积压、平台异常、人工关联。
- [x] 更新根README，把“设计阶段”改为已实现的真实功能列表和实际验证结果。

## 4. 关键测试矩阵

| 编号 | 场景 | 期望 |
| --- | --- | --- |
| T01 | 页面只填账号保存 | 草稿成功，列出缺项，不能直接上传 |
| T02 | 同一账号重复新增/换套餐再上传 | 本地唯一约束和交付约束阻止绕过重复上号规则 |
| T03 | auth_json缺字段/id_token空串 | 除id_token可空外逐项检查；缺字段允许草稿但阻止上传 |
| T04 | 凭证JSON含未知额外字段 | 保存、编辑、上传快照全程保留 |
| T05 | 只PATCH一个Token字段 | 其他字段和未知字段不被清空；明文不出现在响应 |
| T06 | 已保存秘密为空/掩码占位误提交 | 明确报错或省略保持，不能以掩码替换Token |
| T07 | RFC3339带偏移、跨日日期、闰日 | 正确解析；业务日期不被UTC转换改变 |
| T08 | 凭证过期但套餐未过期 | 显示凭证过期，不把套餐有效当授权有效 |
| T09 | 代理密码含@、:、/、Unicode及IPv6 | 正确编码、连接、脱敏；不污染host或path |
| T10 | 代理URL指向回环/元数据/DNS重绑定 | 按默认策略拒绝；管理员显式允许的测试私网单独覆盖 |
| T11 | 导入代理与绑定代理不同 | 展示差异并阻断未解决冲突，不静默替换 |
| T12 | 两标签页同时编辑 | 后写者收到409且可刷新/合并，不覆盖新版本 |
| T13 | 预检后修改代理/凭证/连接 | 原预检失效；提交或Worker阶段校验版本 |
| T14 | 重复点击上传、前端断线重试 | 同一幂等键返回同一任务，不新增远端提交 |
| T15 | 上传已送达但响应超时 | outcome_unknown，不自动重发；可人工关联已有ID |
| T16 | 上传中进程被终止并重启 | 恢复为不确定结果，不无条件重试发送 |
| T17 | 平台400/403/401/非JSON错误 | 分别标记输入/权限/平台鉴权等，不泄密、不误判账号运行状态 |
| T18 | 提交成功后wait_check超过5分钟 | 显示等待与超时提醒，不能直接判失败或在线 |
| T19 | 新增平台状态/null/账号缺失 | 保留原值/未知，不转为正常或0消耗 |
| T20 | metrics.cost恒0 | 不写入金额账本、不展示实时0元误导 |
| T21 | 同一累计窗口反复同步 | upsert覆盖，总请求和Token不重复增长 |
| T22 | 日账单12.34元被修订为13.00元 | 1234分替换为1300分，revision增加，不变成2534分 |
| T23 | 101账号/7天边界/90天最早日期 | 正确分批、按平台时区校验窗口和日期边界 |
| T24 | 批量第二批失败 | 已成功数据保留，失败可重试，游标不错误越过缺口 |
| T25 | 修改已交付账号代理或代理本身认证 | 所有受影响记录out_of_sync，不宣称远端已切换 |
| T26 | 没有远端更新/删除能力 | UI/API不伪造该功能；本地归档说明其实际范围 |
| T27 | 无OpenAPI Token但网页已登录 | 明确缺少独立OpenAPI配置，不读取浏览器Cookie代替 |
| T28 | 页面关闭后任务完成 | 后台任务继续；重新打开显示持久结果 |
| T29 | 日志、审计、API错误、浏览器存储检查 | 无密码、原始Token、代理认证URL和完整请求载荷 |
| T30 | 数据库备份后恢复并轮换密钥 | 可解密、金额一致、任务不重复上传，旧密钥退役受控 |
| T31 | 代理检测期间修改端点，旧检测稍后成功 | 旧版本结果仅存历史，新版本仍需检测，不误判健康 |
| T32 | 同一业务日多次查询且end逐次变化 | 稳定业务日桶只保留当前累计，不产生可重复相加的多行 |
| T33 | 两个本地UUID并发创建同一账号标识 | 数据库identity_key唯一约束阻止重复，不只靠UI检查 |
| T34 | 有人工关联历史ID但无采集记录，或已有交付尝试/数据后修改连接origin或时区 | 三种情况均返回CONNECTION_IDENTITY_LOCKED，旧平台ID不发往新origin |
| T35 | 两次同步后发先至/租约超时后旧响应迟到 | generation条件写入，不覆盖新状态、账单和游标 |
| T36 | 代理来源决议后凭证或绑定再次变更 | 旧决议失效，必须重新核对，不以旧勾选状态放行 |

## 5. 验证层级

| 层级 | 方法 | 必须覆盖 |
| --- | --- | --- |
| 纯逻辑测试 | Go单元测试、前端纯函数测试 | 校验、JSON合并、身份匹配、时区、金额、状态映射 |
| 数据集成测试 | 临时SQLite + migrations | 唯一约束、事务、并发版本、队列租约、快照幂等与日账单去重 |
| HTTP契约测试 | httptest + Mock SupplierAdapter | DTO、秘密字段、错误码、CSRF、任务202、上游异常 |
| UI流程测试 | 前端组件测试 + Playwright | 手工录入/JSON回填/代理/预检/上传跟踪/消耗/并发冲突 |
| 网络探测测试 | 受控HTTP/SOCKS测试代理 | 协议、远端DNS、认证、IPv6、超时、SSRF和重定向 |
| 故障恢复测试 | 可控中断/恢复 | 发送中不重放、游标不跳过、账单不重计 |
| 真实联调 | 获准账号与平台连接 | 特殊凭证字段、套餐授权、代理传递、接收ID、验证结果和账单 |

Mock足以开发和验证本地流程，但不能证明Claude自动授权、远端代理实际出口或平台长期刷新行为成立。

## 6. P1 扩展门槛

| 功能 | 前置事实/需求 | 实现要求 |
| --- | --- | --- |
| 自动登录授权 | 平台认可的凭证样本、字段生成规则、所需授权方式明确 | OAuth/人工交接流程适配，验证码/登录挑战不能伪造；不记录密码日志 |
| 自动刷新凭证 | 刷新责任与远端更新接口明确 | 每账号互斥、轮换Token原子落库、失败保留旧版本、远端同步确认 |
| 远端换代理 | 官方更新接口及生效时机明确 | 版本化变更、确认远端生效、失败可回滚或人工处理 |
| 官方剩余额度 | 可使用且语义明确的额度接口 | 明确5h/7d窗口与重置时间，不使用Token消耗估算冒充 |
| 多角色 | 有实际协作需求 | admin/operator/viewer，权限矩阵与审计独立测试 |
| PostgreSQL与多Worker | 有SQLite争用/可用性证据 | 专用SQL迁移、跨进程租约/锁、Scheduler唯一性、迁移演练 |
| 通知 | 明确收件渠道和触发规则 | 仅有意义异常/恢复通知，去重，不发送凭证 |

## 7. 首版发布的完成定义

仅当以下条件均满足时，才将首版标记为可交付：

1. 表单和JSON两种入口均能走通同一服务端链路。
2. 代理管理和固定绑定可见、可测、可审计；远端生效边界明确。
3. 上传接收、验证和运行状态分开；未知结果不会造成自动重复上号。
4. 请求/Token、离线金额和手工初始余量三个概念不混用。
5. 新鲜度、部分失败、缺项与平台未开放能力在页面清晰呈现。
6. 相关测试、类型检查、lint、构建和恢复演练通过，真实联调差距已明确列出。
7. 没有“假按钮”“假在线”“假自动授权”，文档中列出的能力与发布包一致。
