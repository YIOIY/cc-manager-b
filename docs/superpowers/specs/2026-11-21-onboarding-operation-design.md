# 上号弹窗操作优化（短设计）

## 目的
不改流程结构（连接 → 补充资料 → 确认），只消除现有流程里卡手的地方：代理默认值、按钮为何禁用、代理问题暴露太晚、授权结果多点一次、失败提示不可操作、批量上号时反复重开弹窗。

## 目标 / 非目标
- 目标：6 条操作优化（见下）。
- 非目标：不照搬参考图的 5 步结构与视觉；不放开「不选代理直连」的限制；不做封号规律分析。

## 方案
- A（采用）：在现有组件内逐条优化，后端只在开始授权时加一次代理连通检查。
- B：重构为 5 步向导。改动大、测试需重写，且与「只做操作优化」的诉求不符。

## 设计
1. 代理默认值（`OnboardingProxyPicker` / `useAccountOnboarding`）：打开弹窗时，若没有启用的代理且用户有创建权限，默认「填写新代理」；否则默认选中 localStorage 记住的上次代理（仍启用时）。提交成功后记住本次代理。
2. 禁用原因（`AccountFormDialog`）：「登录 Claude」不可用时，在按钮旁显示单一原因（先选平台 / 先选代理 / 新代理尚未检测保存），点击跳到对应字段。
3. 授权前连通检查（后端 `claudeOAuthStart`）：选了代理时，用与换 token 相同的 HTTP 客户端，经代理向 `https://platform.claude.com` 发一次 HEAD/GET（10 秒内）。连接失败返回 422 `OAUTH_PROXY_UNREACHABLE`「所选代理连不上 Claude，请更换代理后重试」。任何 HTTP 状态码都算可达（403 等需到换 token 时才能判断）。可通过测试钩子替换探测函数。
4. 授权结果（`ClaudeOAuthPanel`）：「打开授权页」为主按钮，复制为次要；粘贴事件中若 `ParseResult` 同等规则能解析出授权码（前端做宽松判断：含 `code=` 的 URL、或 `code#state` 形态），自动触发 exchange。
5. 换 token 失败（`ClaudeOAuthPanel` → `AccountFormDialog`）：后端区分网络错误与业务错误（已有文案），前端识别 `OAUTH_PROXY_UNREACHABLE` / 「无法连接」文案时显示「更换代理」按钮，点击滚动到代理选择并聚焦。
6. 继续添加（`AccountFormDialog` / `useAccountOnboarding`）：首次上号提交成功后不直接关闭，显示成功页「已提交 xxx」，提供「继续添加下一个」（保留平台与代理，重置其余字段并回到第一步）和「完成」。重新授权 / 完善资料场景维持原行为。

文案、间距沿用现有风格；每条配最小单元测试；e2e `claude-oauth.spec.ts` 若受影响同步调整。
