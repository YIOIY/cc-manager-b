# 仪表盘改版（短设计）

## 目的
仪表盘数据不少，但顶部 8 个数字有重复，「要我处理的」和「看看就好的」混在一起，也看不出闲置浪费。改版后，打开页面先回答：还有多少能用、花了多少、有多少要我处理、什么时候要续。

## 目标 / 非目标
- 目标：顶部 4 个指标；需要处理列表按可挽回程度排序；新增闲置账号面板；低频面板折叠。
- 非目标：不做封号规律分析；不改消费趋势和配额看板本身。

## 方案
- A（采用）：重排现有面板 + 小幅扩展 insights 接口（闲置列表、最早到期日）。
- B：纯前端。闲置账号无法可靠计算——配额列表按 5h 用量倒序截断到 50 条，低用量账号正好被截掉；也拿不到套餐到期日。所以选 A。

## 设计
1. 顶部 4 个指标：可用容量（在用 / 总数，平均 7 天余量）、消费（今日、7 天、日均与变化）、需要动手（封禁/失败、接近限额）、到期节奏（7 天内、30 天内、最早到期日）。去掉与之重复的累计行。
2. 需要处理：后端排序在「封禁 / 失败」内部，把可重新授权的状态（login_failed、re_login_failed、sync_failed）排在硬封禁前面。
3. 闲置账号：insights 新增 `idle`，取平台在列、状态 using、7 天用量 < 10% 的账号，带到期日与剩余天数，按剩余天数倒序（剩得越多越浪费），最多 20 条。
4. insights 的 composition 新增 `next_expiry`（未过期的最早到期日）。
5. 账号构成、最近上号、系统状态收进底部折叠区；任一同步异常时默认展开。
