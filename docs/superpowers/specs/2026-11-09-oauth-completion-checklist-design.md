# 授权后补齐清单（设计记录）

日期：2026-11-09。范围：`web/src/components/AccountFormDialog.vue`、`web/src/components/ClaudeOAuthPanel.vue`、`web/src/model/account-form.ts` 及测试。后端、校验规则、`auth_json` 字段不变。

## 意图

Claude 授权只能填充 `auth_json` 13 个字段中的 11 个加套餐和注册日期。密码、套餐起止日期、设备标识、平台连接、代理（未选时的 `proxy_url`）必须人工补充。现状是这些缺项分散在三个区块和一个折叠区里，只靠一条笼统警告和底部折叠的"还有 N 项"提示，用户容易直接提交后被后端打回。

## 目标 / 非目标

- 目标：授权成功（或粘贴 JSON）后，用户一眼看到还差什么、在哪填、填完了没有；提交时缺项不发请求而是定位到缺项。
- 非目标：不改 OAuth 流程、不猜测或生成设备标识、不改接口和后端校验、不做分步向导。
- 反目标：用默认值或随机值顶替拿不到的字段。

## 考虑过的方案

1. 只给缺失字段加高亮：改动小，但仍然容易被忽略，缺项依旧散落。
2. 分步向导（授权 → 补资料 → 确认）：改动大，丢失一屏看全的上下文，编辑已有账号的路径也要重做。
3. **清单 + 字段标记 + 提交拦截（选定）**：授权成功后面板收起为"已授权"摘要，紧随一张"还差 N 项"清单，清单项可跳转到字段并实时变绿；缺项字段带"待补充"标记，自动填充字段带"已自动获取"标记；提交时若有缺项则滚动到第一个缺项并高亮。

## 行为细节

- `ClaudeOAuthPanel` 新增 `summary` 属性（邮箱、组织名、套餐、令牌到期），非空时渲染紧凑成功态：勾选图标、邮箱、组织 · 套餐 · 到期时间、「重新授权」按钮；隐藏步骤说明、链接、结果输入与网络提示。「重新授权」回到生成链接态。
- `account-form.ts` 新增 `completionChecklist(edit, ctx)`：返回有序清单项 `{ key, label, hint, done, anchor }`，覆盖：交付密码、套餐开始/结束日期、设备标识、平台连接、代理（未选代理且 `proxy_url` 为空时）、套餐（未识别时）、账号邮箱（授权未返回时）。`anchor` 是字段 DOM id，供"去填写"滚动聚焦。已配置密码或保留已保存凭证的编辑场景按现有规则视为完成。
- `AccountFormDialog`：
  - 授权成功 / 粘贴成功后进入"补齐模式"（`completionMode = true`），显示清单卡片，替换原来的两条 alert；`warnings` 里来自后端的告警保留显示在清单顶部。
  - 设备标识输入从折叠区提到清单卡片内直接可填；其余凭证字段仍在"查看全部凭证字段"折叠区。
  - 缺项字段 `el-form-item` 加 `is-pending` 类（琥珀色左边框 + "待补充"小标）；自动填充的字段显示灰色"已自动获取"标。
  - 页脚按钮旁常显"还差 N 项 / 可以上号"。点击提交时若 `missingAccountFields` 非空：不发请求，滚动并聚焦第一个缺项，闪一次高亮。
  - 未进入补齐模式（全手填）时保持现有布局，但提交拦截同样生效。
- 保留现有邮箱一致性校验和 `applyOAuthResult` 的原子替换语义。
