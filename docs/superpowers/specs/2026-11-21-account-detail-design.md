# 账号详情弹窗（短设计）

## 目的
已上号账号的「查看详情」只有 5 项信息且全部与卡片重复。改成这个账号的完整档案与操作入口：用量趋势、完整资料与封禁原因、最近动作、常用操作。

## 目标 / 非目标
- 目标：对已上号（linked）状态重做；复用现成的 `platform-usage-history` 接口；操作入口放进弹窗。
- 非目标：未上号 / 提交中 / 失败 / 未知状态的弹窗不动；不做封控规律分析；趋势图只展示用量数字；后端不新增接口。

## 方案
- A（采用）：前端重做 linked 分支，新增趋势图与最近动作两个组件。
- B：后端新增聚合接口一次返回全部。多一层维护，现有接口已够，不采用。

## 设计
1. 趋势图（`AccountUsageTrend`）：7 / 30 天切换；5h 与 7d 占用画折线，每日花费画柱。累计花费按日取当天最后一个快照后做差，首日不画（无基准）。快照多时均匀抽样到约 240 个点。无 `accounts.usage` 权限或无数据时显示说明。
2. 完整资料：套餐起止、注册时间/地区、支付方式、设备、余额、充值日期、质保期、标签、备注、代理、凭证/密码是否已配置、所属用户。封禁原因展示全文与时间。
3. 最近动作（`AccountActivity`）：审计事件（`resource_type=account&resource_id=<id>`，需 `audit.view`）与上号任务（`/jobs?account_id=<id>`，需 `jobs.view`），合并按时间倒序取 8 条；没有对应权限就不请求。注意：平台状态变化本身不写审计，所以不会出现「状态变为已封禁」。
4. 操作入口：分配、修改平台资料、重新授权（条件与卡片一致，共用判断函数）；账号邮箱与平台 ID 可复制。
5. 弹窗宽度：已上号时 720px，其余状态保持 600px。
