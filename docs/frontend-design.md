# CC Max 上号器前端详细方案

文档版本：1.0  
设计日期：2026-11-04  
状态：目标设计方案；当前已有 Vue 3 原型页面，未覆盖的高级交互以 README 的实现状态为准。

本文定义独立上号管理后台的页面、表单、状态、交互和前端工程边界。后端接口与字段最终以 [API 契约](api-contract.md) 为准；平台已公开的能力和待确认项以 [平台对接说明](platform-contract.md) 为准。

## 1. 产品目标与首版范围

操作人员能够通过 Web 页面录入已有 Claude 账号、补全授权凭证、选择代理、提交 CC Max 平台，并持续查看每个账号的状态、请求量、Token 和离线金额消耗。

首版包含：

- 页面填写账号信息，保存不完整草稿，逐字段填写或导入授权凭证。
- JSON 导入与表单回填，批量预检和逐条处理结果。
- 本地代理池管理、健康检查、账号固定绑定与代理关联账号查看。
- 上传预检、异步上传任务、平台验证跟踪和异常处理。
- 账号详情、实时消耗与离线账单看板。
- 平台连接配置、任务中心、应用登录及操作审计。

首版不承担模型调用转发、用户 API Key 分发、充值计费、自动注册账号或购买订阅。自动授权获取是预留扩展：尚未确定平台特殊字段的生成规则前，页面不能把“填写邮箱密码”描述为可以自动完成上号。

## 2. 技术方案

| 项目 | 选择 | 约束与用途 |
| --- | --- | --- |
| UI 框架 | Vue 3 + TypeScript | Composition API，`strict` 模式；业务对象与 API DTO 分离 |
| 构建 | Vite | 开发时代理本地 `/api/v1`；生产与后端同源部署 |
| 组件库 | Element Plus | 表单、表格、抽屉、日期选择、确认框；业务语义由项目组件封装 |
| 路由 | Vue Router | 页面入口、查询参数和受控详情导航 |
| 服务端状态 | TanStack Vue Query | 列表、详情、任务与统计查询；统一失效、重试和轮询 |
| 本地 UI 状态 | Pinia | 侧栏、列表显示偏好、会话权限摘要；不重复缓存服务端业务实体 |
| 图表 | ECharts | 请求/Token 趋势与账单趋势；没有历史数据时不伪造曲线 |
| HTTP | 浏览器 Fetch 封装 | 统一错误、超时、取消、请求 ID 和同源会话；不直连供应商平台 |
| 表单校验 | TypeScript 规则 + Element Plus 表单 | 只改善交互；服务端预检始终是上传判定依据 |

以上为拟采用依赖，本文不表示已经安装。实施时锁定维护中的兼容版本和 lockfile，先完成最小纵向功能，再按实际需求引入组件；图表能力可以在消耗页阶段再加入。

所有平台 OpenAPI 请求、Token 刷新、代理检测与任务执行都由 Go 后端完成。前端不接收平台 OpenAPI Token 的明文回读结果，不在浏览器执行带 Claude 凭证的平台代理调用。

## 3. 信息架构与路由

| 路由 | 页面 | 主要内容 |
| --- | --- | --- |
| `/login` | 应用登录 | 登录本地上号器；与供应商平台登录及 Claude 登录分开 |
| `/dashboard` | 总览 | 库存、待补全、待上传、异常账号、待处理任务、数据新鲜度 |
| `/accounts` | 账号列表 | 筛选、批量选择、平台状态、代理、今日消耗、进入详情 |
| `/accounts/new` | 新增账号 | 页面填写为主，JSON 导入回填为辅 |
| `/accounts/import` | 批量导入 | 文件/文本导入、映射、校验预览、逐条结果 |
| `/accounts/:id` | 账号详情 | 概览、凭证、代理、消耗、任务、审计等标签页 |
| `/accounts/:id/edit` | 编辑账号 | 编辑本地资料，明确已上传数据变更的同步状态 |
| `/proxies` | 代理池 | 本地代理资源、状态、检测、关联账号 |
| `/proxies/:id` | 代理详情 | 脱敏配置、检测历史、绑定账号、维护动作 |
| `/usage` | 消耗中心 | 跨账号查询，实时统计与离线账单分开显示 |
| `/jobs` | 任务中心 | 上传、预检、代理检测、同步等任务与结果 |
| `/jobs/:id` | 任务详情 | 当前步骤、逐项结果、脱敏错误、下一步动作 |
| `/settings/platform` | 平台连接 | 平台地址、Token 设置状态、连接测试与能力摘要 |
| `/system-settings` | 系统设置 | 全局每日上号上限、可上号时段（需 `settings.view`） |
| `/audit` | 操作审计 | 操作者、对象、动作、时间、结果、请求 ID |

账户、代理、任务三类资源均使用本地 UUID 字符串 ID 路由。平台上传返回的账号 `id` 在界面标为“供应商账号 ID”；平台指标中的 `aid` 标为“平台运行账号 ID”，避免混用。

列表筛选和分页可以写入 URL 查询参数，例如状态、套餐、页码、日期范围。邮箱、密码、Token、代理认证信息以及原始 JSON 不写入 URL。

## 4. 页面布局与关键流程

### 4.1 总览

首屏优先回答“哪些账号可以继续处理、哪些账号需要处理”。

- 指标卡：本地总账号、待补全、可提交、平台待验证、平台在线、平台异常、无有效代理、后台同步失败。
- 今日消耗卡：请求、输入 Token、输出 Token、离线账单金额；分别带来源和采集时间。
- 待处理清单：上传结果待核实、平台验证失败、凭证过期、代理失效、同步失败。
- 最近任务：类型、完成数量、失败数量、开始时间、状态。

总览数值来自后端聚合，不由当前分页列表相加。没有采集到数据时显示 `— / 尚未同步`，不能显示 `0` 暗示已确认没有消耗。

### 4.2 账号列表

默认展示：

| 列 | 展示规则 |
| --- | --- |
| 账号 | 邮箱或登录 ID，详情跳转；不包含密码 |
| 套餐 | Max 5x、Max 20x 或 Pro |
| 本地准备状态 | 草稿、待授权、待补全、可提交等后端计算状态 |
| 平台状态 | 原始状态对应中文标签、最后确认时间；未知原值仍可查看 |
| 代理 | 名称、地区、健康标签；地址脱敏 |
| 凭证有效期 | 有时区的到期时间；临近到期高亮，未知明确标注 |
| 套餐有效期 | 开始/结束日期；与 Token 有效期分开 |
| 今日消耗 | 请求、输入/输出 Token；离线金额独立提示延迟 |
| 最近任务 | 类型、结果、失败原因摘要 |
| 操作 | 详情、编辑本地资料、预检、提交、同步、归档等受支持动作 |

筛选项包括套餐、本地状态、平台状态（下拉精确匹配）、代理、代理健康、是否上传、凭证是否到期、标签、日期和账号搜索。搜索旁提供「异常账号」开关：默认隐藏上号失败/待确认、可处理的平台失败态与远端缺失账号（不含已封禁 ban/banned），打开后仅看这些行（URL `abnormal=1`）。筛选由后端执行，前端不假装对全库进行本地过滤。

批量操作区仅在勾选后出现，并显示选中数量及当前作用范围。首版默认“当前已勾选”，不把“全选当前页”自动升级成“全库全选”。批量上传前必须展示每条预检结果；不满足条件的账号不悄悄跳过，而是显示原因。

### 4.3 新增账号页面

采用四段式表单，右侧或底部保留“完成度/待补全项”面板。主操作始终是“保存草稿”；满足提交条件后，出现独立的“预检并提交”步骤。

```text
基本信息          账号、密码、套餐、注册地、套餐日期
代理绑定          从代理池选择、测试、新增代理
授权凭证          逐字段填写 / JSON 导入回填
补充信息          余量、支付方式、设备、质保、标签、备注

底部操作          保存草稿    校验信息    提交平台
```

“JSON 导入回填”先在当前表单预览差异，再确认覆盖字段。导入不会绕过表单和后端校验，不覆盖没有明确提供的新值，也不会自动触发上传。

未保存修改离开页面时显示保存/放弃选择。首版不把含秘密的草稿写入 LocalStorage、SessionStorage、IndexedDB 或 service worker 缓存；需要恢复时使用后端已保存草稿。

### 4.4 提交前检查

1. 保存本地账号，并返回最新版本号。
2. 选择目标平台连接（只有一个可用连接时可预选并显示名称），请求后端预检，获得字段错误、警告、代理检测新鲜度、平台配置/权限核实程度与重复提交检查结果。未实测权限显示“尚未验证”，不能把配置通过当作授权通过。
3. 页面展示拟提交的非敏感摘要：平台、账号、套餐、日期、代理名称、标签；秘密只显示“已提供”。
4. 操作者点击“提交平台”，通过 `POST /api/v1/accounts/{id}/submit` 发送 `Idempotency-Key` 和 `expected_version`，收到 `202` 后进入任务详情；同一次业务提交的网络重试复用同一幂等键。
5. 返回平台账号 ID 后显示“平台已接收，等待验证”；继续通过后台同步更新平台状态。

后端在真正执行任务前重新校验账号版本和凭证版本。预检通过后又编辑资料时，前端必须使预检结果失效，不能复用旧结果上传新数据。

## 5. 表单字段与校验

### 5.1 基本信息

下表“提交必填”对应平台上传要求，不等于保存草稿的要求。

| 字段 | 控件 | 提交必填 | 校验与说明 |
| --- | --- | --- | --- |
| `plan` | 套餐选择 | 是 | 仅展示平台已授权套餐；已知值为 `claude/cc-max-20x`、`claude/cc-max-5x`、`claude/cc-pro` |
| `account` | 文本框 | 是 | 非空、不含空白字符；首版面向邮箱但不擅自假设平台只接受邮箱 |
| `password` | 密码框 | 是 | 非空；编辑时不填写就从PATCH中省略，保持原密码；不能把空字符串发送给后端当“不修改” |
| `register_location` | 地区选择 | 是 | 当前已知仅 `US`；未来从后端能力配置读取 |
| `register_time` | 日期选择 | 是 | `YYYY-MM-DD`，按日期原样传输，不转为 UTC 时间戳 |
| `plan_start_time` | 日期选择 | 是 | `YYYY-MM-DD` |
| `plan_end_time` | 日期选择 | 是 | `YYYY-MM-DD`；不早于开始日期；已过期显示阻断预检问题 |

账号重复检查只是交互提示，创建和上传时仍以服务端唯一约束/平台返回为准。账号和凭证中的邮箱不一致时要求操作者核对，不能静默重写任一字段。

### 5.2 代理绑定

| 信息 | 控件与交互 |
| --- | --- |
| 本地代理资源 | 可搜索选择器；默认只显示启用项，允许查看禁用项但不能新绑定 |
| 代理摘要 | 名称、协议、地区、出口 IP、最近检测延迟、检测时间、关联账号数 |
| 检测 | 异步“测试代理”，显示进行中/成功/失败，不阻塞整个页面输入 |
| 新增代理 | 抽屉表单，保存成功后回填代理 ID |
| 导入 `proxy_url` | 提示匹配本地代理或创建代理资源；不得自动改成另一个出口 |
| 代理不一致 | 导入凭证代理与选中代理不同时显示差异；必须明确选择后再更新凭证 |

代理账号密码在输入时分开填写，由后端组装 URL 并进行用户名密码编码。界面不要求用户手工拼接带 `@`、`:`、IPv6 等特殊情况的认证地址。列表不能展示完整含认证信息的 URL。

对于已上传账号，本地更换代理只能标为“本地已变更，远端同步能力未确认”。首版不能显示“平台换代理成功”，也不能通过重传账号绕过平台的账号不可重复约束。

来源冲突使用API契约中的 `POST /accounts/{id}/credentials/proxy-resolution` 解决，显示“采用已绑定代理”或“采用导入代理”。后者先创建/复用本地代理并核对原导入地址；确认结果由后端连同账号、凭证和代理版本持久保存，不只保留一个前端勾选框。代理健康结果必须属于当前配置版本，旧端点的检测不能满足当前预检。

### 5.3 授权凭证

凭证区提供以下模式：

| 模式 | 首版行为 |
| --- | --- |
| 逐字段填写 | 展示平台要求字段，按字段校验；密码与 Token 默认隐藏 |
| JSON 导入 | 解析对象或 JSON 字符串，回填已知字段，保留额外字段 |
| 登录授权获取 | 能力开关默认关闭；显示“尚未配置授权适配器”，不能假装点击后可工作 |

平台要求的字段如下：

| 字段 | 控件 | 提交规则 |
| --- | --- | --- |
| `id_token` | 隐藏文本输入 | 字段必须存在；允许空字符串 |
| `access_token` | 隐藏文本输入 | 非空字符串 |
| `refresh_token` | 隐藏文本输入 | 非空字符串 |
| `last_refresh` | 带时区时间文本/辅助选择 | 合法 RFC3339 时间，保留实际偏移 |
| `email` | 文本框 | 非空；与账号不一致时明确提示 |
| `account_uuid` | 文本框 | 非空；未经平台确认不施加自造的 UUID 版本限制 |
| `organization_uuid` | 文本框 | 非空 |
| `organization_name` | 文本框 | 非空 |
| `claude_device_ids` | 可编辑字符串数组 | 选填；未填时提交由服务端（及上号表单）自动生成 UUID |
| `type` | 文本框/未来能力驱动选择 | 非空；合法枚举待确认，不提供虚构默认值 |
| `expired` | 带时区时间文本/辅助选择 | 合法 RFC3339 时间；到期凭证不能提交 |
| `proxy_url` | 由绑定代理展示脱敏摘要 | 支持 `http://`、`https://`、`socks5://`、`socks5h://`；必须与确认的绑定一致 |
| `verification_status` | 文本框/未来能力驱动选择 | 非空；语义和允许值待确认，不自动填 `verified` 等猜测值 |

表单允许展开查看“额外字段”。刚导入的数据可在当前内存表单编辑；已保存的数据仅显示额外字段名、类型和存在状态，不通过元信息接口读取未知字段原值，因为其中可能包含秘密。编辑已知字段时，提交补丁语义由后端将新字段与原有凭证合并；未知字段原样保留。不能使用一个仅包含已知字段的新对象把额外字段清空。

已有凭证详情通过 `GET /api/v1/accounts/{id}/credentials/metadata` 只返回字段完整性、有效期、版本与脱敏摘要。编辑页面中，已保存的秘密字段显示“已有值”，不把星号作为实际内容发回服务端。替换单个秘密字段需要明确编辑动作；无需为了修改备注而重新输入全部 Token。

基本资料与凭证分开保存：账号 `POST/PATCH` 只处理基本资料、只写密码和 `proxy_id`；凭证通过 `PUT /accounts/{id}/credentials` 完整替换或 `PATCH` 合并更新。前端必须区分这两个动作，不能误用完整替换清空未回读的秘密。

### 5.4 补充信息

| 字段 | 控件 | 规则 |
| --- | --- | --- |
| `balance` | 百分比输入 | 可选，`0–100`，不带 `%`；标注“录入时余量”，不能冒充实时官方配额 |
| `payment_method` | 选择框 | 可选；已知支付方式按后端能力字典展示，文档中的拼写疑点由后端阻断未知枚举 |
| `register_device` | 选择框 | 可选，Mac / Windows / Linux |
| `recharge_time` | 日期选择 | 可选，`YYYY-MM-DD` |
| `warranty_period` | 天数选择 | 可选，已知 1 / 7 / 30；不把页面 `<1天` 标签自行改成新的接口值 |
| `tags` | 多选 | 可选，界面“速刷coding”“coding”互斥；提交上游时映射为“速刷”“慢蒸”；上号后不支持远端修改 |
| `remark` | 多行文本 | 可选；展示后端长度限制，按纯文本渲染 |

## 6. JSON 与批量导入

### 6.1 单账号导入

用户可以在新增/编辑页上传 JSON 或粘贴文本。先选择“完整账号数据”或“仅授权凭证”，避免将凭证 JSON 误认为完整上号记录。

- 完整账号数据：映射账号、套餐、日期、补充信息和 `auth_json`。
- 仅凭证：只更新凭证区，未提供的账号/套餐/日期保持原值。
- 支持平台允许的 `auth_json` 对象或 JSON 字符串，但禁止双重编码后直接上传。
- 解析失败定位到行/列或字段路径；不把原始 Token 带进错误日志。
- 文件大小、批量条数与嵌套深度以 API 契约的上限为准；超限在发送前提示，后端再次限制。

### 6.2 批量预览

预览表包含行号、账号、套餐、日期是否完整、代理是否匹配、凭证完整性、是否重复和结果。秘密字段不进入表格。

批量导入先调用 `POST /api/v1/imports/preview`，只接收 `import_id` 与脱敏逐行结果，再通过 `POST /api/v1/imports/{id}/commit` 确认入库。原始文件不能依赖浏览器持久缓存保存。

导入账号库与提交平台是两个独立动作。导入允许合法的不完整草稿；用户随后筛选“可提交”账号发起上传。部分导入成功时保留逐条结果，重试仅作用于明确失败项，不重复导入成功项。

批量导入错误报告只含行号、账号脱敏标识、字段路径和错误原因，不回传原始凭证。操作结束清理前端文件文本和导入结果中的秘密引用。

## 7. 状态设计

一个“状态”字段不能承担所有含义，页面分别展示：

| 维度 | 含义 | 页面原则 |
| --- | --- | --- |
| 本地准备状态 | 草稿是否完整、凭证/代理是否可用 | 后端计算；前端即时规则只作提示 |
| 上传状态 | 未提交、排队、提交中、平台已接收、结果待核实、失败 | 上传成功不等于平台可用 |
| 平台运行状态 | 最近查询获得的远端状态 | 保留原始值、观测时间和来源 |
| 凭证状态 | 未配置、字段不全、格式完整、临近到期、过期、未知 | “格式完整”不表示平台验证成功；与套餐日期分开，不仅凭Token外观判真伪 |
| 代理状态 | 未检测、健康、不健康、禁用、检测过期 | 检测成功不等于目标 Claude 服务一定可用 |

已知平台状态映射：

| 原值 | 中文标签 | 操作提示 |
| --- | --- | --- |
| `online` | 在线 | 最近观测正常；同时显示观测时间 |
| `store` | 平台状态：store | 业务含义待平台确认，不等于本地未提交或已验证通过 |
| `offline` | 离线 | 展示平台信息，允许重新同步 |
| `banned` | 已封禁 | 保留证据，不自动删除账号 |
| `wait_check` | 待验证 | 平台说明通常约 5 分钟验证，超时仅提示检查 |
| `check_fail` | 验证失败 | 展示可用的失败原因；无公开更新接口时不承诺可自动修复 |
| `arrearage` | 欠费 | 仅展示状态，不在上号器提供充值操作 |
| `fault` | 故障 | 显示最近错误和同步时间 |
| `suspended` | 已暂停 | 不猜测暂停原因 |
| 空值/新值 | 未知 / 原始值 | 不回退成在线或离线，保留后端原值 |

网络查询失败只更新“同步失败/数据可能过期”，不把上次 `online` 擅自变成平台 `offline`。操作员手动刷新和后台定时同步发生并发时，以后端记录的新观测版本为准。

## 8. 账号详情页

### 8.1 概览标签页

展示本地资料、平台 ID、套餐、注册信息、所有状态维度、最近上传与最近同步结果。对缺失信息直接提供“补全资料”入口。

### 8.2 凭证标签页

展示“字段是否提供、字段是否有效、到期时间、最后刷新时间、版本号、来源”。Secret 默认不回读；首版可以只提供替换，不提供批量导出明文。若后续增加授权查看/导出，应单独设计权限、短时二次确认和审计，不使用列表接口顺带返回明文。

“重新授权/刷新”按钮由后端能力标记控制。未配置适配器时给出原因，不发送必然失败的任务。

### 8.3 代理标签页

展示当前绑定、导入时的代理来源、最近健康结果和更换历史。对于已上传账号分别显示“本地绑定版本”和“最近确认上传的代理版本”，避免本地变更被误认为远端已生效。

### 8.4 消耗标签页

实时指标与离线账单拆成两个面板：

- 实时：请求数、输入 Token、输出 Token、成功率、平台状态、查询区间、采集时间。
- 离线：请求数、输入/输出 Token、缓存读写 Token、人民币金额、日期范围、采集时间。
- 首版不展示官方 5h/7d 剩余额度进度条，除非后端已经具备经过验证的数据源；上传时填写的 `balance` 不能充当实时额度。
- 趋势图仅使用后端返回的非重叠时间桶；不能把每次查询的累计值连起来当增量消耗。

### 8.5 任务与审计标签页

任务显示执行步骤、尝试次数、结果分类和脱敏原因。审计显示操作主体和配置/状态变更摘要，不显示密码、Token、代理认证信息或原始上传载荷。

## 9. 代理池页面

### 9.1 列表和详情

列表列出名称、协议、地址摘要、期望地区、实际出口 IP、最近延迟、健康状态、最近检测时间、绑定账号数、启停状态和到期时间（如录入）。地区没有可靠检测结果时显示“未确认”。

代理详情包含配置摘要、检测历史和关联账号表。关联账号可以进入详情，但不能在代理页面批量导出账号凭证。

### 9.2 新增和编辑

表单字段：名称、协议、主机/IP、端口、用户名、密码、地区、备注、启用状态，可选到期时间。支持 IPv4、IPv6 与域名，后端负责最终解析、DNS/出口访问规则和 URL 编码。

编辑已有代理密码时使用“保持现有值/替换”语义，不能将脱敏占位值作为新密码保存。绑定账号的代理配置发生变化时展示影响账号数量；变更作为本地操作记录，不承诺平台已同步。

### 9.3 测活和异常

- 单个检测和批量检测均生成后台任务，前端显示任务进度。
- 检测结果至少包含时间、成功/失败、延迟、出口 IP、错误摘要；可用地区仅在可靠来源存在时展示。
- 首版检测失败只更新健康状态，不自动修改代理启停配置；前端不能自行禁用。后续如增加连续失败自动禁用，必须由明确后台策略控制。
- 代理不可用时不触发账号随机换代理；固定绑定账号显示“代理不可用，待处理”。
- 有绑定账号的代理不直接硬删除；首版优先禁用/归档，最终行为由后端关联约束决定。

## 10. 消耗中心

页面分为“实时请求与 Token”和“离线账单”两个 Tab，日期选择、字段和新鲜度提示各自独立。

| 维度 | 实时面板 | 离线账单面板 |
| --- | --- | --- |
| 时间输入 | 带时区提示的时间范围 | 自然日范围 |
| 平台限制 | 主动向平台查询单次最多7天；更长历史仅显示后端已保存且覆盖完整的数据 | 主动补采开始日期不得早于90天前；更早日期仅显示本地已保存数据 |
| 批量账号 | 后端按最多 100 个账号分批 | 后端按最多 100 个账号分批 |
| 金额 | 不展示实时金额 | 接收 CNY 整数分，按元展示两位小数，不用浮点数累计 |
| 延迟说明 | 页面标注约 2 分钟 | 页面标注约 2 小时 |
| 空值 | `—`，缺失不等于 0 | `—`，未出账不等于 0 |

平台实时 `cost` 已停用且恒为 0，前端不能把它显示为“今日消费 0 元”，也不能与离线金额相加。账单 `cost` 是平台消费，不命名为“结算收入”“利润”或“已到账”。

成功率使用后端明确聚合的结果；不能对各账号百分比简单平均后声称是全局请求成功率。累计值、时间桶和最后一次采集快照不得混合求和。

当日指标使用稳定业务日桶，实际观察截止时间单独展示；手动刷新和后台采集并发时只接受服务端最新代次。平台连接已有平台关联（含人工关联历史ID）、交付尝试或采集记录任一项后，origin与时区不可编辑；需要变更时新增连接，原账号ID和历史账单不自动迁移。

图表配套提供可读表格、时间范围和采集时间。支持排序与筛选，CSV 导出若实现应由后端输出脱敏统计，不包含账号密码和凭证。

## 11. 任务中心与异步交互

所有长操作先创建任务，再由前端查询进度。具体任务类型、状态、终止/重试能力以 API 契约为准，前端不能自行枚举可重试错误。

任务详情至少显示：任务 ID、类型、目标数量、发起人、创建时间、开始/完成时间、当前步骤、成功/失败/待核实数量、逐条结果和请求 ID。

上传请求超时可能意味着“平台已接收但本地未拿到响应”。此时显示“提交结果待核实”，禁止自动再次上传同一账号。人工核实流程由后端提供相应操作；没有公开列表接口时不能承诺能自动查回丢失 ID。

取消任务仅在后端声明 `cancellable` 时显示。已经发送到平台的上传不能显示“取消成功且未上号”；前端要区分“停止剩余本地任务”和“撤销远端操作”。

## 12. 状态管理、请求与轮询

### 12.1 状态归属

| 状态 | 存放位置 |
| --- | --- |
| 账号、代理、任务、统计、配置摘要 | Vue Query，由服务端响应驱动 |
| 当前登录主体与权限摘要 | Pinia 或会话查询缓存，不含会话秘密 |
| 表格显示偏好、侧栏折叠 | Pinia；可选持久化非敏感偏好 |
| 未保存表单、刚输入的秘密 | 组件/页面内存，提交或离开后清理 |
| CSRF 凭证等协议状态 | 按后端会话方案处理；不进入 URL、不做业务持久缓存 |

生产会话使用同源 Cookie 方案，具体属性和 CSRF 防护以 API 契约为准。浏览器不持有平台 Bearer Token，也不把本地登录 Token 拼到 URL。

### 12.2 查询 Key

查询 Key 包含资源类型、本地 ID、筛选、分页和日期区间，例如 `accounts + normalizedFilters`、`account + localId`、`accountUsage + localId + range + source`、`job + jobId`。这些是前端缓存标识，不是后台接口名称。

列表/详情编辑成功后统一使对应 Key 失效；上传任务结束后刷新账号、任务、总览；代理编辑后刷新代理和关联账号摘要。UI 不依赖手写跨页面事件维持一致性。

### 12.3 轮询策略

以下是初始 UI 策略，可由后端返回建议间隔：

| 页面 | 活跃时建议间隔 | 说明 |
| --- | --- | --- |
| 执行中的任务详情 | 2–5 秒 | 仅读取本地任务状态，不等于每次调用平台 |
| 账号列表/总览 | 30–60 秒 | 读取后端缓存和快照 |
| 单账号状态 | 30–60 秒 | 平台观测约 2 分钟延迟，不高频打平台 |
| 消耗与账单 | 页面进入/手动刷新，后台同步后失效 | 离线数据不做秒级刷新 |

页面隐藏时停止常规轮询，返回后重新拉取；任务结果由后端持续执行，不依赖页面打开。失败指数退避并保留旧数据，自动重试仅用于读取；写请求不能因 Fetch 重试机制重复提交。

首版不使用 WebSocket/SSE。若后续需要推送，应使用同源会话和明确授权，不能把长期访问 Token 拼进订阅 URL。

## 13. 权限与敏感信息

首版 P0 采用单管理员登录，前端按后端能力显示操作，后端独立执行所有权限校验。只读/运营等角色作为 P1 预留，不将多角色管理作为首版阻塞条件。后续可区分只读、运营、管理三类能力：

- 只读：查看脱敏账号、状态、统计和任务结果。
- 运营：创建/编辑本地账号、导入、预检、上传与维护任务。
- 管理：平台连接、代理池配置、系统配置和审计查询。

具体角色授权以 API 契约为准；界面隐藏按钮不是权限边界。首版账户列表不包含多用户角色分配页面。

约束：

- 密码、Claude Token、平台 Token、代理密码不进入前端日志、监控埋点、错误报告或 URL。
- 不自动复制秘密到剪贴板；复制账号标识、任务 ID 和脱敏错误可以提供快捷按钮。
- 平台 Token 配置保存后仅显示“已配置、更新时间”，没有“读取原 Token”。
- 脱敏错误按文本渲染，禁止通过 `v-html` 渲染外部错误和备注。
- 秘密输入不被通用表单自动持久化；是否使用密码管理器由操作员决定，应用不强制保存。
- 退出登录清理查询缓存和内存表单；会话失效也执行相同清理。
- 本地账号归档、禁用与平台停用严格区分；没有远端接口就不提供伪装的远端动作。

## 14. 错误、空态与可访问性

| 场景 | 页面行为 |
| --- | --- |
| 字段错误 | 字段下显示原因，同时有顶部错误摘要；提交后聚焦第一个错误 |
| 代理不可用 | 阻断需联网的授权/上传预检，保留已填写数据并提供检测入口 |
| 平台 Token 未配置 | 给出配置入口；不把所有账号标为凭证失效 |
| 平台返回未授权套餐 | 套餐旁展示错误，保留原信息，管理员核对授权 |
| 重复账号 | 指向可访问的本地重复项；平台重复只展示平台证据，不猜测其远端 ID |
| 版本冲突 | 提示资料已被他人修改，允许查看最新摘要，不静默覆盖 |
| 同步失败 | 展示旧数据、时间和失败状态，不清空历史值 |
| 尚无账号 | 引导“新增账号”和“JSON 导入” |
| 尚无消耗 | 区分未同步、查询无数据和确认为 0 |
| 无权限 | 显示不可操作原因，避免按钮点击后才统一报错 |

所有表单控件有可关联标签；必填不能只靠红色星号表达。健康状态同时使用文字和颜色。表格操作支持键盘访问，弹窗打开后管理焦点，关闭后回到触发位置。图表提供表格替代和单位说明；长任务进度不能用频繁的读屏播报干扰操作。

桌面优先，最小可用布局覆盖 1280px 左右工作台；窄屏将账号详情摘要改为卡片，复杂表格允许横向滚动，关键动作保持可见。不能为响应式而隐藏账号状态、代理异常或数据时间。

导入解析器、字段映射和金额/日期格式化适合纯函数。平台状态归并、去重、上传幂等、配额判断、代理自动禁用、账单聚合属于后端业务逻辑。

## 16. 前端验收矩阵

实施时将本节转为组件测试、API 集成测试和浏览器验收，不为文档本身编写实现镜像测试。

| 编号 | 场景 | 验收结果 |
| --- | --- | --- |
| FE-01 | 页面填写不完整账号并保存 | 成功保存草稿，不能直接上传，待补全项准确 |
| FE-02 | 全部必填信息完整 | 后端预检通过后可以创建上传任务 |
| FE-03 | 导入完整 JSON 后改备注 | 额外凭证字段保留；未修改秘密不被星号覆盖 |
| FE-04 | 导入仅凭证 JSON | 回填凭证，账号套餐日期不被清空 |
| FE-05 | `id_token` 为空 | 允许；其他必填凭证为空时阻断提交 |
| FE-06 | RFC3339 带不同时区偏移 | 展示/传输不丢偏移，日期字段不发生跨天转换 |
| FE-07 | 账号与凭证邮箱不一致 | 明确提示并要求核对，不静默修正 |
| FE-08 | 未配置自动授权适配器 | 不提供可执行的虚假授权流程，说明未配置原因 |
| FE-09 | 代理密码含 `@`/`:`、IPv6 主机 | 页面接受分字段录入，最终URL由后端正确处理且界面脱敏 |
| FE-10 | 批量代理检测 | 显示独立任务与逐项结果，切换页面后任务继续 |
| FE-11 | 已上传账号更换本地代理 | 显示远端同步待确认，不显示平台已换代理 |
| FE-12 | 平台上传返回成功 | 标记平台已接收，显示账号 ID，不能直接标在线 |
| FE-13 | 上传响应超时 | 显示结果待核实，不能通过自动重试重复上传 |
| FE-14 | 实时 `cost=0` | 不显示实时消费0元，不与离线账单合计 |
| FE-15 | 离线金额及缓存Token | 单位、字段与来源正确，显示约2小时延迟及采集时间 |
| FE-16 | 字段为 `null` 或未采集 | 显示未知/无数据，不显示确定的零值 |
| FE-17 | 平台查询失败 | 保留旧状态和观测时间，标同步失败 |
| FE-18 | 新平台状态值 | 原值可见并标未知，不崩溃、不误判在线 |
| FE-19 | 超过100个账号查询 | 前端只请求本地后端，后端分批；页面呈现部分成功/失败 |
| FE-20 | 多标签页同时编辑 | 冲突可感知，不静默覆盖新版本 |
| FE-21 | 未登录调用/已声明不可用的操作 | 首版会话鉴权有效；后续多角色页面按能力限制，直接请求仍由后端拒绝 |
| FE-22 | 浏览器存储、URL、日志检查 | 无密码、Token、代理认证或原始JSON |
| FE-23 | 键盘操作新增/弹窗/错误导航 | 焦点正确、标签可读、状态不只靠颜色 |
| FE-24 | 页面隐藏或关闭后再打开 | UI轮询暂停/恢复，后台任务与采集独立运行 |

## 17. 开发顺序

1. 建立工程、同源登录、路由、布局、错误处理和只读账号列表。
2. 完成新增/编辑草稿、手动凭证表单、JSON 回填和后端字段错误映射。
3. 完成代理 CRUD、检测任务、固定绑定和关联账号查看。
4. 接入服务端预检、上传任务、待验证/待核实状态和任务详情。
5. 接入实时请求/Token、离线账单、时间范围与数据新鲜度。
6. 完成批量导入、批量上传、审计、权限与浏览器端验收。
7. 在平台补齐授权字段和更新接口规范后，再启用自动授权/续期能力。

前端交付的完成标准是上述流程可通过真实后端及受控平台适配器验证，而不是页面按钮齐全。平台未开放或未核实的能力必须保持明确不可用状态。
