# 帮助文档入口设计（2026-11-13）

## 为什么做

上号的同事（如 `tokenupload`）在页面上遇到问题时没有地方查：设备标识从哪里取、「上号到」该选哪个平台、403「当前供应商未获授权该厂商」是什么意思、链接为什么复制不了。项目里与上号相关的文档（`docs/claude-oauth-onboarding.md` 等）是写给开发和运维的，混着接口路径和内部实现，不适合给操作员看。用户要求：页面上有一个文档入口，里面是操作手册和常见问题。

## 目标 / 非目标 / 反目标

- 目标：侧边栏有「帮助文档」入口，所有登录用户可见；内容分「操作手册」和「常见问题」两组；可按关键字搜索；每个主题有固定地址，可从上号弹窗直接跳到对应主题。
- 非目标：不做在线编辑、不做权限分级的文档、不做多语言；不把 `docs/` 下的开发文档搬上页面。
- 反目标：文档里出现服务器地址、令牌、密码等内部信息；文档与页面上的实际文案对不上；为了看文档丢掉正在填写的上号表单。

## 方案比较

| 方案 | 做法 | 取舍 |
| --- | --- | --- |
| A 结构化内容（采用） | 内容写成 TypeScript 数据（主题 → 段落/步骤/提示/命令块），由一个页面组件渲染 | 无新依赖；可测试（主题 ID 唯一、站内链接有效）；可搜索；随版本发布。改内容要发版 |
| B Markdown 渲染 | 打包 `.md` 文件，引入 Markdown 渲染库用 `v-html` 输出 | 写起来顺手，但要新增依赖并处理 HTML 输出；主题定位和搜索要另做 |
| C 后端读 `docs/` | 新接口把仓库文档发给前端 | 现有文档不面向操作员，且镜像里不带 `docs/`；还要加接口和权限 |

选 A：内容量小（十几个主题），更看重和页面一致、能定位到具体主题。

## 设计

- 路由 `/help`（`name: 'help'`，标题「帮助文档」，`nav: true`，不设权限），排在导航最后。当前主题由查询参数 `?topic=<id>` 决定，缺省或无效时显示第一个主题。
- 内容：`web/src/help/content.ts` 导出 `helpTopics`。每个主题 `{ id, group: 'manual' | 'faq', title, keywords?, blocks }`；块类型：`p` 段落、`steps` 有序步骤、`list` 无序列表、`note`（`info`/`warn`）提示、`code` 可复制的命令、`link` 站内跳转到另一主题。
- 搜索：`searchTopics(topics, query)` 纯函数，对标题、关键字和所有块文本做不区分大小写的包含匹配；空查询返回全部。
- 页面 `web/src/views/HelpView.vue`：左侧按组列出主题并带搜索框，右侧显示当前主题；命令块带复制按钮（复用 `copyText`）；搜索无结果显示「没有找到相关内容」。窄屏时左右改为上下。
- 入口：
  1. 侧边栏「帮助文档」。
  2. 上号弹窗标题旁「上号手册」链接 → `/help?topic=onboard`。
  3. 「设备资料」字段提示里的「如何获取？」→ `/help?topic=device-id`。
  弹窗里的两个链接都在新标签页打开，不影响正在填写的表单。
- 首版内容（措辞与页面文案一致）：
  - 操作手册：上号前的准备；新建并上号（三步）；获取设备标识；查看上号结果与重试；修改平台资料；平台连接设置；看懂仪表盘。
  - 常见问题：「当前供应商未获授权该厂商」；「上号到」里平台选不了；授权链接无法复制 / 已失效；授权后还差几项；「结果待确认」；删除平台连接被拒；网页通道已暂停；仪表盘「平台未开通」「未出齐」；修改平台资料提示重新打开；登录不上。
- 设备标识主题只说明真实来源（该账号实际登录 Claude Code 的电脑上 `~/.claude.json` 的 `userID`）和填写位置，并注明供应商未说明格式要求、被拒时联系供应商。

## 留给实现者

样式沿用现有页面的卡片与配色；主题图标、块的具体样式自行决定。
